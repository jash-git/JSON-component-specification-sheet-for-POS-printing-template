# 印表範本修改教學手冊（給非資訊背景同事）

> 版本：1.0 ｜ 對象：無程式背景、需修改印表範本的同事
> 目標：看懂範本結構、能獨立完成「日常 90% 的修改」、知道哪些事情不能做

---

## 第 0 章：課程總覽與學習路徑

### 課程資訊
| 項目 | 說明 |
|---|---|
| 總時數 | 12 小時（4 個單元，每單元 3 小時，建議分 2 天） |
| 上課方式 | 簡報 30% + 實機操作 70% |
| 事前準備 | 每人一台已安裝編輯器（Notepad++ 或 VS Code）的電腦、一台測試印表機、練習用範本檔 |
| 評量方式 | 每章課後練習 + 期末實作考（修改一張真實發票範本） |

### 能力分級（學完後你會什麼）
| 等級 | 能力 | 對應章節 |
|---|---|---|
| LV1 會看懂 | 知道檔案每一行在幹嘛 | 第 1~3 章 |
| LV2 會修改 | 改字、改大小、移位置、換圖 | 第 4~6 章 |
| LV3 會調整邏輯 | 加條件、加欄位、調表格 | 第 7~9 章 |
| LV4 會除錯 | 印不出來、跑版時知道怎麼查 | 第 10 章 |

### 給學員的一句話
> 「這不是程式課。範本檔就像一張『透明描圖紙』，上面貼滿了便利貼，
> 每一張便利貼寫著『這裡要印什麼字、貼在哪裡、多大張』。
> 你的工作只是：看懂便利貼、換掉上面的字、偶爾把便利貼挪個位置。」

## 第 1 章：印表機與紙張的基礎常識（60 分鐘）

### 1-1 我們用的兩種印表機
| 印表機 | 用途 | 注意事項 |
|---|---|---|
| 熱敏印表機（80mm） | 收據、發票 | 紙寬設錯**不會**壞，但內容會被切掉 |
| Godex 標籤機（DT-2205） | 標籤貼紙 | 紙張尺寸設太小會**直接不能印（紅燈閃爍）** |

⚠️ **第一條鐵律：改 Godex 標籤機範本時，Width 只能大不能小，改完先印一張測試。**

### 1-2 最重要的換算：8 個點 = 1 公分 ÷ 10（1mm）
我們的印表機是 203 DPI，換算口訣：

> **「8 點 1 毫米，80 紙 640 點」**

| 你想留的寬度 | 要填的 pixel |
|---|---|
| 1 mm | 8 |
| 5 mm | 40 |
| 10 mm | 80 |
| 57 mm 紙張全寬 | 456 |
| 80 mm 紙張全寬 | 640 |

練習：客人想讓店名離左邊 2 公分，X 要填多少？（答案：160）

### 1-3 常用字級對照表（已量測過，直接背）
| 效果 | 字體大小設定 | 實際高度約 |
|---|---|---|
| 一般字 | 9 | 最小 |
| 單倍字 | 13 | 5 mm |
| 雙倍字 | 28 | 11 mm |
| 四倍字 | 40 | 13 mm |
| 發票標題 | 16 | 6 mm |

口訣：**字高 ≈ 字級數字 ÷ 2.5（mm）**，抓不準就往上加一點。

## 第 2 章：範本檔的長相——一棵倒過來的樹（90 分鐘）

### 2-1 一段真實的範本長這樣
```json
{
  "ElementType": "Page",
  "X": 0, "Y": 0, "Width": 80, "Height": 0,
  "ChildElements": [
    {
      "ElementType": "Text",
      "X": 0, "Y": 0, "Width": 640, "Height": 48,
      "Content": "{$StoreName}",
      "ContentSize": 28, "ContentBold": "Y",
      "X_Alignment": "Center",
      "Y_Alignment": "Increment"
    },
    {
      "ElementType": "QrCode",
      "X": 0, "Y": 0, "Width": 120, "Height": 120,
      "Content": "{$InvoiceQrCode}",
      "Y_Alignment": "Increment"
    }
  ]
}
```

### 2-2 用「公司組織圖」來理解
- **Page = 整張紙**：永遠只有一張，在最上面
- **ChildElements = 部門名單**：告訴印表機「這張紙上有哪些東西」
- **每個元件 = 一位員工**：各自有自己的位置(X,Y)、佔位(Width,Height)、工作內容(Content)

### 2-3 10 種元件，你只需要先記 5 種
| 元件 | 白話解釋 | 使用頻率 |
|---|---|---|
| Text | 一段文字 | ⭐⭐⭐⭐⭐ |
| QrCode | QR Code | ⭐⭐⭐⭐ |
| Image | 圖片（店招 Logo 等） | ⭐⭐⭐ |
| Rows | 重複的明細列（一筆一行） | ⭐⭐⭐⭐ |
| Block | 一整列（區塊） | ⭐⭐⭐ |
| Table | 有沒有資料要不要印的判斷區塊 | ⭐⭐ |
| BarCode | 條碼 | ⭐ |
| IncludePage | 插入另一張範本 | ⭐⭐（進階） |
| Embedded / CommandMode / Page | 系統用，**不要手動改** | — |

> 課後練習 2-A：在練習檔中找到店名的元件，指出它的 X、Y、ContentSize 各是多少。

## 第 3 章：位置與對齊——便利貼要貼哪裡（90 分鐘）

### 3-1 座標系：原點在左上角
```
(0,0) ──────────────────→ X 變大（往右）
  │
  │   店名貼這裡 (X=0, Y=0)
  │   電話貼這裡 (X=0, Y=56)  ← Y 是「往下幾毫米」
  ↓
 Y 變大（往下）
```

### 3-2 兩個偷懶神器：讓機器幫你算位置

**X_Alignment（水平）**
| 值 | 意思 |
|---|---|
| `X` | 用我填的 X 值（預設） |
| `Right` | 靠右對齊 |
| `Center` | 置中 |

**Y_Alignment（垂直）** —— 這是排版自動化的關鍵
| 值 | 意思 | 白話 |
|---|---|---|
| `Y` | 用我填的 Y 值 | 我自己決定高度 |
| `Increment` | **上一個元件的底 + 1** | 接著上一個下面排 |
| `Element` | 跟上一個元件**同一行** | 排在它右邊 |

### 3-3 黃金法則
> **日常修改只要記：把 Y_Alignment 設成 Increment，然後盡量不要手填 Y。**
> 機器會自動把東西往下排，不會重疊。手填 Y 是進階玩家才做的事。

### 3-4 改錯了會怎樣？
- 兩個元件 Y 一樣 + 都靠左 → **字疊在一起**
- Width 超過紙寬（80mm 紙 > 640）→ **右邊被切掉**
- Height 填 0 或 -1 → 機器自動算（通常沒事），但文字建議抓字高表

課後練習 3-A：把「謝謝惠顧」改成置中、粗體、雙倍字，印出來確認。
課後練習 3-B：故意把兩個元件的 Y 設成一樣，觀察疊字，再改回 Increment。

## 第 4 章：文字元件 Text——最常打交道的朋友（90 分鐘）

### 4-1 Text 常用參數一覽（照使用頻率排序）
| 參數 | 型態 | 說明 | 常用值 |
|---|---|---|---|
| Content | 文字 | 要印什麼（可混變數，見第 5 章） | `"{$StoreName}"` |
| ContentSize | 數字 | 字多大 | 9 / 13 / 16 / 28 / 40 |
| ContentBold | Y 或 N | 粗體 | `Y` |
| X_Alignment | 文字 | 水平對齊 | `Left` / `Center` / `Right` |
| Width | 數字 | 這段文字多寬（pixel） | 紙寬 640 就填 640 |
| Height | 數字 | 多高 | 對照 1-3 字級表 |
| AutoWrap | Y 或 N | 太長換行(Y) 或 截斷(N) | 預設 Y |
| Rotation | 數字 | 0 或 180（倒著印） | 0 |
| SecondContent | 文字 | 主要內容是空的時候改印這個 | 備援欄位 |
| IntervalSymbols | 文字 | 多筆資料合併時的分隔符號 | `","` |

### 4-2 三種最典型修改
**① 改字體大小**
```json
"ContentSize": 13   →   "ContentSize": 28
```

**② 改對齊**
```json
"X_Alignment": "Left"   →   "X_Alignment": "Right"
```

**③ 改固定文字（不變的內容）**
```json
"Content": "統一編號：{$TaxID}"
```
> 注意：中文、冒號都可以直接寫；`{$...}` 是「到時候換成真資料」的佔位符。

課後練習 4-A：發票標題改為四倍字置中。
課後練習 4-B：在地址後面加上「(本店免用統一發票)」固定文字，並確認長度不會超出紙寬（太長就開 AutoWrap 或縮 ContentSize）。

## 第 5 章：資料綁定——`{$...}` 是什麼意思（60 分鐘）

### 5-1 核心觀念：佔位符
列印當下，系統會把 `{$變數名}` 換成訂單真實資料：
```json
"Content": "日期：{$OrderDate} 單號：{$OrderNo}"
```
印出來可能是：`日期：2026-09-11 單號：A20260911001`

### 5-2 常用變數速查表（依實際系統為準）
| 變數 | 內容 | 變數 | 內容 |
|---|---|---|---|
| `{$StoreName}` | 店名 | `{$OrderNo}` | 單號 |
| `{$OrderDate}` | 日期 | `{$Total}` | 總金額 |
| `{$TaxID}` | 統編 | `{$Address}` | 地址 |
| `{$Phone}` | 電話 | `{$InvoiceNo}` | 發票號碼 |

完整清單請洽資訊部門索取《變數對照表》。

### 5-3 鐵律
1. **變數名打錯一個字 = 印出空白**。不確定就複製貼上，不要手打。
2. 變數大小寫有差（`{$OrderNo}` ≠ `{$orderno}`）。
3. 同一行可以塞很多個變數，中間用任意文字連接。

課後練習 5-A：做出 `電話：{$Phone} 地址：{$Address}` 的頁尾。

## 第 6 章：圖片、QR Code、條碼（60 分鐘）

### 6-1 Image（店招 Logo）
```json
{
  "ElementType": "Image",
  "X": 0, "Y": 0, "Width": 264, "Height": 88,
  "Content": "{$LogoFile}",
  "X_Alignment": "Center",
  "Y_Alignment": "Increment"
}
```
- 標準 Logo 尺寸：**寬 33mm(264px) × 高 11mm(88px)**，已量測好直接套用
- `{$LogoFile}` 是系統放 Base64 圖檔的地方，**不要動它**

### 6-2 QrCode
```json
{
  "ElementType": "QrCode",
  "Width": 120, "Height": 120,
  "Content": "{$InvoiceQrCode}",
  "ErrorCorrection": "H",
  "Y_Alignment": "Increment"
}
```
- ErrorCorrection = 容錯率（髒污破損還能不能掃），**H(30%) 最保險，一律用 H**
- 尺寸常見 120×120（15mm）或 160×160，依版面配置

### 6-3 BarCode（極少用）
- Format 決定條碼種類（EAN_13、CODE_128…），**改之前先問資訊部門**

課後練習 6-A：把發票 QR Code 從 120 加大到 160，觀察是否與下方文字重疊（若重疊代表下方元件的 Y 是手填的，改回 Increment）。

## 第 7 章：明細表格——Rows / Block / Table（120 分鐘）

### 7-1 為什麼需要特殊元件？
買 3 樣商品，明細就有 3 行；買 20 樣就有 20 行。**不可能一行一行寫死**，所以要用「迴圈元件」。

### 7-2 Rows：一筆一行的明細
```json
{
  "ElementType": "Rows",
  "RootName": "INVOICEDETAILS",
  "ChildElements": [
    { "ElementType": "Text", "Content": "{$ProductName}", "Width": 300 },
    { "ElementType": "Text", "Content": "{$Qty}", "Width": 80 },
    { "ElementType": "Text", "Content": "{$Price}", "Width": 120 }
  ]
}
```
- `RootName` = 資料陣列的名字（發票明細就叫 `INVOICEDETAILS`）
- 裡面的 Text 是「每一行長什麼樣子」，系統自動重複印
- 橫向排列技巧：子元件 Y_Alignment 都設 `Element`，就會排在同一行

### 7-3 DisplayMode：單筆一行 vs 多筆合併
| 值 | 效果 | 適用 |
|---|---|---|
| `Single` | 每一筆單獨一行 | 明細、清單 |
| `Merge` | 多筆併成一行，用 IntervalSymbols 分隔 | 備註、口味標示（例：`{"Content":"{$Topping}", "DisplayMode":"Merge", "IntervalSymbols":","}` 印出「珍珠,布丁,仙草」）|

### 7-4 Block（一列）與 Table（整塊要不要印）
- **Block**：一次一整列的內容（例如「小計列」），可帶條件
- **Table**：包著 Rows/Block 的外框，參數 `AlwaysPrint`：
  - `Y`：就算沒資料也印（例如固定要有的表頭）
  - `N`：沒資料整塊消失（例如「統編欄位」只在有統編時出現）

課後練習 7-A：在明細加一個「單位」欄位（假設變數 `{$Unit}`），排在數量後面。
課後練習 7-B：把備註欄改為 Merge 模式，用「、」分隔。

## 第 8 章：條件顯示——什麼時候該印、什麼時候不印（120 分鐘）

### 8-1 情境：客戶有統編才印統編欄
這就是「條件顯示」。三個參數一起用：

| 參數 | 意思 | 例子 |
|---|---|---|
| ConditionalKey | 看哪個變數 | `{$TaxID}` |
| Conditional | 怎麼判斷 | 空白=有沒有資料 / `>` `<` `==` `>=` `<=` `!=` |
| ConditionalValue | 跟什麼比 | `"0"`、`"VIP"` |

### 8-2 兩種最常用的寫法

**① 單純「有就印、沒有就不印」（90% 的情況）**
```json
"ConditionalKey": "{$TaxID}",
"Conditional": "",
"ConditionalValue": ""
```
> Conditional 和 ConditionalValue 都留空 = 只要 TaxID 有內容就印。

**② 數值比較（例：滿千才印折扣列）**
```json
"ConditionalKey": "{$Discount}",
"Conditional": ">",
"ConditionalValue": "0"
```
唸法：「當 Discount > 0 的時候印」。

### 8-3 判斷符號對照（會唸就會用）
| 符號 | 唸法 | 例子：什麼時候印 |
|---|---|---|
| 空白 | 有資料就印 | 統編欄位 |
| `>` | 大於 | 折扣 > 0 |
| `<` | 小於 | 找零 < 1000 |
| `==` | 等於 | 付款方式 == 現金 |
| `!=` | 不等於 | 狀態 != 作廢 |

### 8-4 哪些地方可以放條件？
Block、Rows、CommandMode、IncludePage——幾乎所有「成區塊」的元件都行。

課後練習 8-A：新增「貴賓您好」列，只在 `{$MemberLevel}` == `VIP` 時印出。
課後練習 8-B：新增「免費停車券」區塊，只在 `{$Total}` >= 500 時印出。

## 第 9 章：IncludePage——範本呼叫範本（60 分鐘，進階）

### 9-1 概念：樂高積木
有些內容很多張單據都要用（例如統一的頁尾），就做成一個小範本，需要的範本用 `IncludePages` 呼叫它。

### 9-2 重要規則（不要問為什麼，照做）
1. **被呼叫的頁面永遠在最後印**
2. **不能讓 A 呼叫 B、B 又呼叫 A**（系統有防呆，但你也不要試）
3. 常見屬性：`SinglePage: "Y"` = 另起一張紙印（例如發票一定要獨立一張）

> 這章只需「會看」，日常修改碰到 IncludePage 先**連絡資訊部門**。

## 第 10 章：除錯手冊——印壞了怎麼辦（60 分鐘）

### 10-1 症狀對照表
| 症狀 | 最常見原因 | 解法 |
|---|---|---|
| 標籤機紅燈閃、不印 | Width/Height 比實際標籤小 | 調大，且先印測試頁 |
| 內容右邊被切掉 | 超過紙寬（80mm>640 / 57mm>456） | 縮 Width 或開 AutoWrap |
| 字疊在一起 | 兩個元件 Y 相同 | 改 Y_Alignment 為 Increment |
| 某欄印空白 | 變數名打錯/大小寫錯 | 對照變數表，複製貼上 |
| QR 掃不出來 | 太小或容錯率太低 | 加大、ErrorCorrection 設 H |
| 明細只印一筆 | Rows 的 RootName 打錯 | 檢查是否為 `INVOICEDETAILS` |
| 整段不見了 | Table 的 AlwaysPrint=N 且沒資料 | 檢查條件設定 |
| 改完完全沒變 | 改錯檔案／系統快取 | 確認路徑、重啟測試程式 |

### 10-2 除錯三步驟
1. **縮小範圍**：把懷疑的元件以外的部分先刪掉（複製一份再刪），看還會不會壞
2. **對照法**：找一張「好的」範本，逐項比對參數
3. **還原法**：改動前先備份，一次只改一個地方，壞了就改回去

### 10-3 修改前檢查清單（印出來貼在螢幕旁）
- ☐ 檔案備份了嗎？（複製成 `xxx_備份_20260911.json`）
- ☐ 一次只改一項嗎？
- ☐ 變數名是複製貼上的嗎？
- ☐ Width 沒超過紙寬嗎？
- ☐ 存檔後有實際印一張測試嗎？
